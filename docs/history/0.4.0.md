# Changelog history - [0.4.0] - 2026-10-29

Frozen record moved verbatim out of `CHANGELOG.md` when the changelog was split. **Append-only: do not restate
or re-derive these numbers.** They are measurements of the runs that produced them, and a number rewritten to
match a newer build describes a run nobody performed.

## [0.4.0] - 2026-10-29

A **MINOR** release by this file's own definition: saving a knob now takes effect without a restart for everything except the
four that cannot, `/settings` and `/issued` were re-laid out around what an operator actually asks, and `mypki serve` now says
why a TLS path is wrong before it tries to bind. Nothing an operator has to re-learn or re-install for — every 0.3.0 route keeps
its address and its form fields, a 0.3.0 data directory opens with no manual step, the CA on disk is untouched, and `<config>/mypki.env`
written by 0.3.0 is read back unchanged. What changed is what a save does, plus two pages' shape.

This release is the response to a Windows field report on 0.3.0 (`PowerShell` host, `MYPKI_SSL_CERTFILE` spelled with doubled
backslashes, `python scripts/smoke_test.ps1` failing to parse). Every item below traces to something that report showed or hid.

### Added

- **A TLS pre-flight before the bind** (`cli._tls_file_problem`, called first in `cmd_serve`, before `configure_logging`). When
  both `MYPKI_SSL_CERTFILE` and `MYPKI_SSL_KEYFILE` are set, each path is checked for existence, readability and "is this a
  directory?", and a failure prints `config error: MYPKI_SSL_CERTFILE points at a file that does not exist: <path>` and exits 1.
  The report's own symptom was `cannot bind 0.0.0.0:8443: [Errno 2] No such file or directory` — an error naming the *socket* for
  a mistake in a *path*. A path containing `\\` also gets a hint naming forward slashes and single backslashes, because that is the
  spelling that was actually typed. A half pair (`--ssl-cert` alone) is still plain HTTP with no refusal: only a pair means TLS.
- **Hot reload on save** (`app._publish_saved_settings`): after `write_settings_file` succeeds, the app rebuilds
  `Settings(_env_file=env_file_layers(previous), …)` — the same construction the next `mypki serve` would perform, validated by the
  same model validators — and installs it as `app.state.settings`, then re-runs `logsetup.configure_logging`. Every issuing limit,
  every CSR subject default, the CA defaults and all five logging knobs therefore apply to the **next request** this server answers.
  `create_app` gained `cli_overrides=`, so a rebuild can keep the flags `mypki serve` was handed instead of losing them; if the
  adoption raises, the save says `Saved to <file>, but this process could not adopt it (<exc>). The values take effect at the next
  start.` rather than claiming success.
- **Preset dropdowns over an authoritative number box** on the Issuing limits (`app.KNOB_PRESETS`, `app.CUSTOM_CHOICE`):
  validity days (30/90/180/365/730/1095/1461), SAN cap (1…1000), CSR size (4096…262144) and session lifetime (300…86400). Each list
  is filtered by `_preset_choices` against the very `Ge`/`Le` objects `config.py` declares, and the `<select>` carries **no `name`
  attribute** — only the number input posts, so a dropdown can never submit a value the server has not bounds-checked. A live value
  that matches no preset (a host running `MYPKI_MAX_SANS=7`) selects `Custom` and shows 7 rather than rounding to 10.
- **A restart marker and a live marker on every knob**: `active only after reboot` (rose) beside the four startup-only knobs,
  `applied now` (green) beside everything else. The page now states which is which instead of leaving it to a footnote.
- **The copy button says one short thing** (`static/app.js`, per the report's brief): `Copied to clipboard`, in green
  (`.copy-note` is `--green` bold; `.copy-note.failed` stays amber and verbose). The 0.3.0 sentence it replaces was honest but long.
- **Two Windows-only test defects fixed** (`tests/test_settings_save.py`): the config-directory assertion now branches per OS
  (`expected_config_home()` reads `%APPDATA%` on Windows, `$XDG_CONFIG_HOME` elsewhere) and compares `Path` objects rather than
  strings. The product code was correct; the test asserted a POSIX path against a Windows host.

### Changed

- **`STARTUP_ONLY_KNOBS` shrank from nine knobs to four**: `host`, `port`, `session_max_age`, `data_dir`. 0.3.0 listed the five
  logging knobs there only because it had no way to re-run `configure_logging`; telling an operator to reboot a working service for
  a knob that *is* live is worse than the ambiguity the list was written to remove. The four remaining are now enforced in code as
  well as on the page: `_publish_saved_settings` re-pins each one from the settings this process actually started with, so a Save
  cannot put `port=8543` into `app.state` on a server still bound to 8443.
- **The resolved-state table is gone**, along with its three note blocks (`What "source" can and cannot tell you`,
  `The order values are read in`, `What is masked, and why`). It restated twenty-odd values a reader could already see in the form,
  and its `Source` column named a layer no process can identify. What it got right survived: the precedence order and the
  indistinguishability sentence moved into the Storage status panel (which renders on a plain GET, not only after a Save), and the
  panel gained a fifth row — **`Data directory came from`** — the one provenance an operator acts on, which reports `set by a
  mypki serve flag` when the value arrived that way. `_settings_rows` is deleted; `_settings_source` stays because that row uses it.
- **The 'Not editable here' card now states what each unmanaged knob currently is** (`app._unmanaged_card`), which is what the
  deleted table used to carry: `MYPKI_SECRET_KEY` as `set (value not displayed)` / unset-with-a-generated-one, both `ssl_*` as
  `set (path not displayed)` or `not set — plain HTTP`, and `config_dir` as the directory this page's own file lives in. Presence,
  never value and never a key path — `tests/test_no_key_leakage.py` still proves that from outside.
- **`/issued` has no Revoked column.** The Status cell carries the pill and, for revoked rows, `revoked <YYYY-MM-DD HH:MM:SS>Z`
  plus the reason. There is now exactly **one** *Revoke Selected*, in the bar above the table (the duplicate below it and its
  `.select-bar.bottom` rule are deleted), and the server-rendered counter reads `0 selected` — the same shape `app.js` writes at
  zero, so one number has one spelling in both languages.
- **`render_settings` takes `just_saved: bool` instead of `saved=`.** This fixes a real 0.3.0 defect a new test found: visiting
  `/settings` on a host that had *ever* been saved rendered a green confirmation block for an action nobody had just taken.
- **README.md and .env.example spell TLS paths out loud** (`SPELL THESE PATHS WITH FORWARD SLASHES, OR SINGLE BACKSLASHES`),
  because the reported failure was a doubled-backslash path that uvicorn could only report as a bind error.

### Fixed

- **`scripts/smoke_test.ps1` did not parse.** Line 782's `$n:` is now `${n}:`; PowerShell read the bare form as an unparseable
  drive-qualified scope. A regex sweep over the file found no other bare `$name:` hazard (the remaining matches are legitimate
  `$env:` / `$script:` scopes). This is a **parse** fix: neither harness has been executed on this box, and `smoke_test.ps1` remains
  runtime-unverified here.
- **Every knob reported itself live.** The `settings applied without a restart` log line compared `MYPKI_*` spellings against field
  names, so nothing ever matched the startup-only set (MEASURED: 21 live / 0 need one). It now compares like with like via a local
  `needs_reboot()` — MEASURED after the fix: 17 live / 4 need one.
- **A dropdown could have been policy instead of convenience.** `_preset_choices` filters presets against `config.py`'s bounds rather
  than trusting the hand-written table, and a preset outside a knob's range is dropped; `tests/test_views.py` asserts that every
  preset rendered *and* that each posting box carries `min=`/`max=` read off `Settings.model_fields`, so the page's promise and
  pydantic's rule cannot drift.

### Known gaps in 0.4.0 (deliberate, not pending work)

- **Revoking still publishes nothing.** No CRL, no OCSP responder, no delete: a stamp is a row in `issued.db` on this host, and a
  client that already trusts the certificate keeps trusting it until it expires. The Status cell now shows *when* the decision was
  made; it does not make the decision visible to clients.
- **Four knobs still need a restart**: `MYPKI_HOST`, `MYPKI_PORT`, `MYPKI_SESSION_MAX_AGE`, `MYPKI_DATA_DIR`. They are marked in red
  on the page and re-pinned in code, but nothing about them can be applied to a live bind.
- **`scripts/smoke_test.ps1` has never been run from this build** (no PowerShell on the Linux host these notes were written on). It
  parses, it is statically balanced, and its needles match `smoke_test.sh` section for section — that is not the same as a measured
  pass, and no Windows number is claimed for 0.4.0.
- **The dropdowns, the checkbox on/off colour and the clipboard line have never been seen in a browser on this host** (none is
  installed). `app.js` is verified by `node --check` and by an assertion on the shipped file; the behaviour remains unobserved here.
- **The adoption-failure path is exercised by injecting a broken `MYPKI_MAX_SANS` into the environment**, not by a real concurrent
  hand-edit of the config file. It proves the message and the file-then-adopt ordering, not the race.
