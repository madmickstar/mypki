The order values are read in, highest first: a real environment variable, then mypki serve flags, then {{ config_file }} (the file this page writes), then ./.env in the working directory. So a save that appears to do nothing usually has a shell variable or a flag sitting above it, and a knob set in a shell stays set no matter what is typed into these boxes.

What "came from" can and cannot tell you: mypki default, supplied by the operator, or mypki default (passed through explicitly) — the last when a value equal to mypki's own default reached this app through an explicit route (a CLI merge, or a constructor), which is worth separating from "nobody said anything". A value that arrived from a .env file, one from a shell variable and one from a command-line flag are indistinguishable here: pydantic-settings resolves that precedence internally and keeps no record of which layer won. Stating the limit is the honest answer — naming a layer this process cannot name would be a guess printed as a fact.
