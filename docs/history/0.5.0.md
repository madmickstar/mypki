Frozen record moved verbatim out of `CHANGELOG.md` when the changelog was split. **Append-only: do not restate

## [0.5.0] - 2026-10-30

A **MINOR** release by this file's own definition: a new page (`/inspect`), a new block on an existing page (`/ca`'s PEM), a new
card position on `/about`, a new sentence on `/settings`, and four new refusals in `mypki serve` before it binds. Nothing an
operator has to re-learn or re-install for: every 0.4.0 route keeps its address and its form fields, the two routes' existing
fields are untouched (`/csr/sign` still posts `csr_pem`, `/settings` still posts the same `MYPKI_*` names), a 0.4.0 data directory
opens with no manual step, the CA on disk is untouched, `<config>/mypki.env` written by 0.4.0 is read back unchanged, and the four
startup-only knobs are still pinned in code exactly as they were.

Two of these items are direct answers to the same Windows field report that drove 0.4.0. The first half of it (a doubled-backslash
`MYPKI_SSL_CERTFILE`) was fixed in 0.4.0; the operator's follow-up was `error: cannot bind 0.0.0.0:8443: [SSL] PEM lib (_ssl.c:4122)`
with both knobs pointing at files that existed — and the second half of this release is what that sentence failed to say.

### Added

- **`GET /inspect` and `POST /inspect`** — a page that reads a pasted PEM and describes it, and refuses nothing (`app.render_inspect`,
  `app.inspect_page`, `app.inspect_submit`; new module `src/mypki/inspect.py`). One form field, `pem_paste`; up to
  `inspect.MAX_BLOCKS_TO_TRY = 8` blocks described; each block rendered as a facts table (Type, Subject, Issuer, Subject Alternative
  Names, Validity (UTC), Serial (hex), SHA-256 fingerprint, Signature algorithm, Public key, BasicConstraints, and for a request the
  rows a request cannot have: "none — a CA sets/assigns them") plus `<ul class="findings">` lines for the things that matter out loud:
  expired with a day count computed from the certificate, not-yet-valid, self-signed, `not a CA`, SHA-1 signature, RSA below 2048,
  Ed25519 (`NOT MODELLED`), an odd SAN mypki would not issue, a tampered CSR signature. Kinds are `certificate`,
  `certificate request`, `private key`, `unreadable`, `unrecognised`, `nothing readable`, `not described`. The page states its own
  limits in four sentences at the top (no chain verification, no trust store, no revocation knowledge, findings are not gates) and it
  works on a host with no CA, because what it describes is the text in the box rather than this server's state.
- **`inspect.describe_pem(paste, max_chars)` refuses exactly one thing**: `RequestTooLargeError` naming `MYPKI_MAX_CSR_CHARS`, raised
  before any parser runs and even when a valid certificate is present in the paste. Everything else becomes a report. The body cap on
  the route is `max_csr_chars + 8192` so the refusal is mypki's sentence rather than starlette's.
- **A pasted private key is named, never opened** (`inspect.redact_private_key_bodies`, `inspect.KEY_BODY_REDACTED`): a
  `PRIVATE KEY` block's base64 body is replaced by one marker before the paste is echoed or logged, its armour line stays so the
  operator can see which block was redacted, and the report for it carries no PEM and no `sha256_of_der`. Certificates in the same
  paste survive byte-identical; a mixed paste reports both. An encrypted key is never prompted for.
- **`/ca` now shows the certificate itself** with a copy button (`app.ca_page` passes `ca_pem`, `ca_download.html` renders
  `<pre class="pem" id="pem-ca">` plus `data-mypki-copy="pem-ca"`). These are the same bytes `GET /ca/certificate` serves as an
  attachment, rendered rather than re-derived, and both harnesses assert byte parity by hashing the DER inside each (see Testing).
- **`mypki serve` now checks what the TLS files contain**, not only whether they exist (`cli._tls_file_problem` second pass, with new
  `cli._certificate_slot_problem`, `cli._private_key_slot_problem`, `cli._is_pem_private_key`). A private key in the certificate slot,
  a certificate in the key slot, unparsable bytes, an encrypted server key (which makes OpenSSL prompt `Enter PEM pass phrase` on
  stdin, unanswerable for a backgrounded process), a key type OpenSSL will not use for TLS, and a cert/key pair that does not match
  (`[X509: KEY_VALUES_MISMATCH]`) each become exit 1 naming the knob. A leaf plus its issuing chain in one file is still accepted.
- **`Settings.raw_path_spelling()`** (new `config._keep_raw_ssl_spellings` wrap validator + private attr): the raw text
  `MYPKI_SSL_CERTFILE`/`MYPKI_SSL_KEYFILE` were configured as, kept because `Path` destroys the spelling on Windows (`str(PureWindowsPath("C:\\a\\b.crt"))`
  collapses the doubled separators, MEASURED on pydantic 2.14.1 / pydantic-settings 2.16.1). `cli._tls_spelling` reads it, so the
  separator hint survives a dotenv layer; `cli.settings_with_cli_overrides` carries the raw text through for whichever half of the
  pair the command line did not name.
- **The seventh nav link** (`base.html`, "Inspect PEM", between About and Settings) with its inline SVG icon. The nav is still plain
  markup: `/inspect` needs no JavaScript, and `static/app.js` gained nothing for it beyond the copy button it already provided.

### Changed

- **The four restart-only boxes on `/settings` show what the file says** (`app._knob_input`'s new `saved_values`/`live_display`
  arguments, new `app._pending_saved_value`, `settings.html`'s `pending_saved` macro, `style.css`'s `.pending-saved`) whenever the
  saved line differs from what this process resolved. Beside the box a rose sentence names what is still running: *"this process is
  still running MYPKI_PORT as 8443; the saved value goes live at the next start."* Before 0.5.0 these four boxes showed the live
  value, which was defensible — the box then matched the bind — but it made a save look like it had done nothing, and the operator's
  own report was "I typed 8444, the box still says 8443". Four rules keep the marker honest (`_pending_saved_value`): not a
  startup-only knob → no marker; a rejected or unadopted save (`overrides`) → no marker; nothing ever saved for that knob → no
  marker; saved equals live → no marker, because a rose line on every startup-only box trains an operator to ignore the one that means
  something. `_publish_saved_settings`' `STARTUP_ONLY_KNOBS` re-pinning is **unchanged**, so no page claims a bind that has not happened.
- **The "what this host is running" card moved to the top of `/about`**, above the lede and the profile hero. Same rows, same context
  keys, one position change: version plus source URL are what a problem report quotes, so they now precede the prose.
- **Findings are not errors** (`style.css` `.findings`/`.finding`): `/inspect` reuses `--amber`, the colour this app already uses for
  "look at this", rather than `--rose`, which it uses for "this was refused or broken". No new colour enters the palette, and the
  block is deliberately not `.form-errors`, which promises "nothing was written, fix this and submit again".
- **`scripts/smoke_test.ps1` resolves its curl by name** (`$script:CurlBin`, `curl.exe` first then `curl`) and builds
  `src/mypki/__init__.py` one `Join-Path` segment at a time. A hard-coded `curl.exe` made the harness print "NOTHING WAS CHECKED" on a
  Linux/macOS host that has curl and a healthy server, and a literal `'src\mypki\__init__.py'` failed `Test-Path` there, silently
  losing the expected version that §3 and §12 compare against.
- **The plain-HTTP banner's advice no longer assumes the default bind** (`cli.cmd_serve`'s warning, `.env.example`'s TLS comment,
  `docs/page-map.md` §6's `serve` row — all three changed together). It used to end "run nginx/Caddy/IIS in front of this **localhost-only**
  origin", which is true of the default bind and wrong for an operator who has already moved `MYPKI_HOST`, while omitting the consequence that matters:
  `https_only` is `settings.tls_enabled`, so with TLS terminated at a proxy the session cookie is not Secure on either side unless the proxy sets it. The
  sentence now names both routes and that cost. `.env.example` carries the same three facts above the two knobs it documents (it had the stale phrase, and
  `cli.py` printed it — fixing one and not the other would have left an operator-facing contradiction). No test asserted the old wording; the assertion now
  reads `"terminate TLS there" in plain.stdout` with the matching negative.

### Testing

- **Gates on Linux, this build:** `ruff check src tests scripts tools` → *All checks passed!*; `ruff format --check src tests` →
  *36 files already formatted*; `mypy src` → *Success: no issues found in 17 source files* (`inspect.py` is the seventeenth);
  `pytest -q --cov=mypki --cov-report=term-missing --cov-fail-under=85` → **662 passed, zero skips**, TOTAL **2700 statements /
  84 missed = 96.89%**. Against 0.4.0's published 554 tests / 2345 statements / 82 missed = 96.50%, the suite gained **108 tests
  and 355 statements**, and `src/mypki/inspect.py` came in at **234 statements, 0 missed — 100%** on its first run. The eight
  remaining misses are spread over `app.py` (37), `cli.py` (15), `csr.py` (7), `settingsfile.py` (5) and others, and the two
  standing holes this release did not touch are `__main__.py` 17-21 and `paths.py` 161, 166-167.
- **New file `tests/test_inspect.py` (58 tests)** asserts both halves of the new page. The module half calls
  `inspect.describe_pem` directly on fixtures built with `cryptography`, because a page whose promise is *never refuse* has to be
  tested against documents mypki would never have issued: an expired leaf (flagged with a day count), a not-yet-valid one, a
  SHA-1-signed certificate and a SHA-1-signed request, an RSA-1024 key, an Ed25519 key (its hash row reads `NOT MODELLED`), a leaf
  carrying GeneralNames mypki would not issue, an IP SAN, a CA-wannabe CSR, a tampered CSR signature, a body that is not base64,
  a body that decodes but is not DER, and an armour kind this app does not know. Two fixture techniques are worth recording: the
  SHA-1 material is re-assembled by hand because cryptography 50 refuses to *sign* SHA-1 at all (MEASURED:
  `UnsupportedAlgorithm: Hash algorithm "sha1" not supported for signatures`), and the RSA-1024 / Ed25519 fixtures exist precisely
  because the issuer-side policy refuses them — `ca.describe_ca` and `keys.describe_public_key` both raise `KeyPolicyError` on
  such keys (MEASURED), which is why `inspect.py` reads certificates with its own DER walk instead of calling either.
- **The redaction assertions are the load-bearing security tests in that file:** a pasted key's base64 must not come back while
  its BEGIN/END lines must, an encrypted key is never prompted for, every key spelling (`PRIVATE KEY`, `ENCRYPTED PRIVATE KEY`,
  `RSA PRIVATE KEY`, an unusual armour) stops at the same branch, redaction leaves a certificate in the same paste byte-identical,
  and a mixed paste counts both. The HTTP half adds the 413 naming `MYPKI_MAX_CSR_CHARS` (and not starlette's
  `Field exceeded maximum size`), a tokenless POST refused **before** the paste is echoed, junk answering 200 with
  *nothing readable*, and the page needing no CA at all.
- **New file `tests/test_nav.py` (30 tests)**, written because nothing in this suite looked at the sidebar before a seventh link
  was added. `base.html` decides which item is `.active` by comparing `request.url.path` against a literal in the template, so a
  route can be registered and render perfectly while its nav item is missing, duplicated or lit on the wrong page — and every
  existing test would have stayed green. These assert seven links in the measured sidebar order, exactly one lit per page, the
  `/csr/sign` → `Sign CSR` sharing that `home()` implies, and `/version` lighting **nothing** (asserted as 0 rather than left
  untested, because a reader would otherwise assume it was a bug).
- **`tests/test_cli.py`'s TLS tests now use real PEM material.** New helper `_server_pair(tmp_path, mismatch=…, chain=…)` writes a
  self-signed certificate plus its key with `cryptography`, replacing 0.4.0's `b"not a real certificate"` bodies: those passed while
  `_tls_file_problem` only asked whether a path existed, and 0.5.0 parses what is inside, so a passing test needs material that
  actually parses and a failing test needs material that fails in **one named way**. `mismatch=True` produces the pair OpenSSL calls
  `[X509: KEY_VALUES_MISMATCH]`; `chain=True` appends a second certificate after the leaf, because leaf-plus-issuer in one file is
  ordinary and must stay accepted. EC P-256 throughout for speed (MEASURED on this box: 0.002 s against 0.146 s for RSA-3072). The

### Known gaps in 0.5.0 (deliberate, not pending work)

- **`/inspect` verifies no chain.** It can name an issuer and print its fingerprint; it cannot say anybody trusts that issuer, and it
  does not try. Its findings are descriptions — the refusing rules stay on `/csr/sign`, where a bad request is refused with a reason
  and nothing is written. A page that both described and enforced would make `/inspect` a second signing policy nobody asked for.
- **`/inspect` knows nothing about revocation**, because this app publishes no CRL and runs no OCSP responder (gotcha 2). A reader
  printing *valid until …* is quoting the certificate, not saying it is still trusted. The page says so in its own words and §15
  asserts that sentence stays.
- **A redacted key keeps its armour line on purpose.** `redact_private_key_bodies` replaces the base64 body and leaves
  `-----BEGIN … PRIVATE KEY-----` / `-----END …` so the operator can see *which* block was redacted — which is why §14's armour sweep
  must never receive a key paste (a correct `/inspect` renders that armour twice) and why §15 asserts the leak test against the
  base64 lines instead.
- **The one refusal `/inspect` makes is about size.** `describe_pem` raises `RequestTooLargeError` before any parser runs, even when a
  valid certificate sits inside the oversized paste; everything else — junk, unreadable DER, an unknown armour kind, a key — becomes
  a report. Up to `MAX_BLOCKS_TO_TRY = 8` blocks are described and surplus blocks are **counted**, not silently dropped.
- **Four knobs still need a restart**: `MYPKI_HOST`, `MYPKI_PORT`, `MYPKI_SESSION_MAX_AGE`, `MYPKI_DATA_DIR`. 0.5.0 changed only what
  those four boxes *display*; `_publish_saved_settings`' `STARTUP_ONLY_KNOBS` re-pinning is untouched, so no page may claim a bind
  that has not happened.
- **Feature C's harness mirror is negative-only.** The harnesses assert zero pending sentences on a host that has never saved, plus the
  wording; the positive case — box shows 8543 while the rose sentence names 8443 — exists only in `tests/test_settings_save.py`
  against a temporary config dir. Neither harness performs a successful save: one would write into the operator's own
  `$XDG_CONFIG_HOME/mypki/` or `%APPDATA%\mypki\` from a script that only means to look.
- **`scripts/smoke_test.ps1` has now been run — on Linux, under `pwsh` 7.6.9.** That is progress against 0.4.0's "never executed",
  and it is not Windows: no PowerShell on Windows, no `%APPDATA%` path, no `certutil`, no CRLF report has ever been observed from this
  box. Every Windows coverage or smoke number in SMOKE_TESTING.md remains a transcription of the operator's own report.
- **`app.js`'s clipboard line and both new CSS rules (`.pending-saved`, `.findings`/`.finding`) have never been seen in a browser on
  this host** — none is installed. `style.css` is asserted as a served asset carrying the expected text, and `app.js` by `node --check`
  plus an assertion on the shipped file.
- **`/ca` now renders a second copy of the root certificate.** That is safe only while the byte-parity assertions hold: §9 compares
  `/ca`'s block against `GET /ca/certificate` by hashing the DER inside each, and §15 hashes a third rendering. If those assertions are
  ever relaxed, the page has grown an unverified second source of truth about what this CA is.
- **An unpacked archive does not test itself in this checkout.** This venv holds an **editable install of `/home/user/mypki/build`**
  (`pip list` reports a stale `mypki 0.1.0` pointing at this directory while `mypki --version` prints 0.5.0), so unpacking
  `mypki-0.4.0.zip` here and running its tests imports **this build's code** — 0.5.0 under 0.4.0's assertions. MEASURED: that run printed
  **2 failed, 552 passed**, and neither failure is a version assertion. `test_packaging.py`'s own 25 tests pass in both trees; what fails is
  `test_cli.py::test_serve_warns_in_plain_http_and_not_at_all_with_tls` (0.4.0 hands junk PEM to a `_tls_file_problem` that now parses contents, so
  exit 1 arrives before the banner) and `test_settings_save.py::test_a_plain_get_after_a_save_does_not_claim_that_a_save_just_happened` (0.4.0 expects
  `value="8443"` in a box 0.5.0 fills with the saved value). Both are newer code under older tests, not defects in the archive — and this release's own
  gate was run against this tree rather than an installed wheel. To judge an archived tree on its own terms, unpack it into a venv where *that* version is
  installed (SMOKE_TESTING.md records the same measurement).
