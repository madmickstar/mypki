## [0.1.0] - 2026-10-26

First release: one root CA created from a terminal, five server-rendered pages, and nothing else — no API surface, no
accounts, no revocation (see *Known gaps* below and README's *Known gaps*, which is the honest list rather than a roadmap).

### Added

- `mypki init-ca` — RSA-3072 / SHA-256 self-signed root with `CA:TRUE pathLength:0`, written to `<data>/ca/` at mode
  0600 on POSIX, refused without `--force` (exit 2) and archived rather than deleted with it. Optional passphrase
  encryption via `--encrypt`; optional `icacls` hardening behind `--secure-acl`, skipped silently where `icacls` is absent.
- `mypki serve` — uvicorn on **127.0.0.1:8443** by default, with a printed warning for any non-loopback bind and a plain-HTTP
  banner unless both `MYPKI_SSL_CERTFILE` and `MYPKI_SSL_KEYFILE` are set.
- `mypki info` — which CA is loaded, its public facts, and the resolved data directory. No `sign`, `revoke` or
  `export-key` subcommand exists on purpose (README *Naming*).
- `GET /` — the root's public facts read from the certificate only: subject, validity, serial, colon-grouped SHA-256
  fingerprint, key spec, and a boolean for "private key present on this host".
- `GET` + `POST /csr/generate` — a private key plus matching CSR shown **once**, optionally encrypted, written nowhere.
- `GET` + `POST /csr/sign` — two steps: validate and show what the CSR actually asks for, then issue with mypki's own
  extension profile for `server`, `client` or `both`. Only SAN is copied from the request; every other extension is a
  server-side constant.
- `GET /ca` and `GET /ca/certificate` — install instructions for Windows / macOS / Linux / Java plus the fingerprint to
  verify out of band, and the root as an attachment named `mypki-root-ca.crt`.
- `GET /issued` — read-only list of what has been signed (serial, type, CN, SANs, validity, issue time). No delete, no
  revoke, no export.
- `GET /version` — HTML reporting the running build's version, so a smoke test can prove which build it talked to.
- Security posture on every response: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`,
  `Referrer-Policy: same-origin`, CSP `default-src 'self'` with no `unsafe-inline`, and `Cache-Control: no-store` on every
  PEM/key/CSR response. Every POST requires a CSRF token; without one nothing is signed (page-map §0).
- Limits as configuration, validated at startup rather than mid-signing: `MYPKI_MAX_CSR_CHARS` (32 000),
  `MYPKI_MAX_SANS` (100), `MYPKI_VALIDITY_DEFAULT_DAYS` / `MYPKI_VALIDITY_MAX_DAYS` (365 / 825 — the ceiling is browser
  policy for locally-issued TLS server certificates, not a preference), `MYPKI_SESSION_MAX_AGE`, and the `MYPKI_LOG_*`
  block bounded at `log_max_bytes * (log_backup_count + 1)`.
- A private-key log filter attached to the root logger and to the `mypki` logger tree: no record containing
  `PRIVATE KEY` reaches the log file or the console mirror (`src/mypki/logsetup.py`).
- `docs/page-map.md` as the citable spec (`page-map §N` in code comments), `.env.example` documenting every knob with what
  it costs, and `SMOKE_TESTING.md` walked automatically by `scripts/smoke_test.sh` (POSIX) and `scripts/smoke_test.ps1`
  (Windows) — both tracked in git and deliberately excluded from the sdist and wheel.
- `tools/check_version.py` — a stdlib-only, import-free, read-only checker for the version chain (module → manifest →
  hatchling pattern → CHANGELOG section → annotated tag), with exit codes that keep "could not check" separate from
  "checked and clean".

### Security

- No response body, header or cookie carries private-key material. Asserted rather than promised by
  `tests/test_no_key_leakage.py`, including the CA key's actual DER bytes and the base64 body without its armour.
- The CA private key is loaded once at startup and never read per request; it is not a route target and never reaches
  `issued.db`, which stores metadata only.
- Oversized input is refused through mypki's own error page naming `MYPKI_MAX_CSR_CHARS`, before the body is parsed, so the
  framework's bare JSON size error cannot surface (page-map §0).

### Known gaps in 0.1.0 (deliberate, not pending work)

No ACME/SCEP/EST, no CRL or OCSP, no intermediate CAs, no HSM, no accounts or approval workflow, no multi-tenancy, no
JavaScript front end, no audit trail. The absence of revocation is why `MYPKI_VALIDITY_MAX_DAYS` exists at all: a
mis-issued certificate can only be waited out, so issue short-lived ones and re-issue rather than revoke.
